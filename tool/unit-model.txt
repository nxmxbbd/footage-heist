# unit-model.txt --- the systemd dependencies of the units a window stops and starts on the target.
#
# tool/test-window.sh simulates exactly this graph (its fake systemctl); night.sh compares it with the target before
# prep / go / rollback and refuses on any difference (recover only warns). A firmware or Protect update that changes
# these units therefore stops the tool instead of silently invalidating the sandbox tests. tool/unit-graph.py reads it.
#
# Validated on: Protect 7.3.70 (systemctl show on the target console, 2026-10-27).
#
# Format (one item per line, '#' comments):
#   unit <name>                    a unit of the window set; the target must report it with LoadState=loaded
#   <name> <Property> [unit ...]   its complete dependency list as `systemctl show -p <Property>` reports it (every
#                                  unit type; order does not matter); Property = Requires Requisite BindsTo PartOf
#                                  Wants Conflicts OnFailure ConflictedBy (+ Upholds UpheldBy PropagatesStopTo
#                                  StopPropagatedFrom OnSuccess, compared only when the target reports them).
#                                  OnFailure and the optional ones must stay empty: the fake does not simulate them
#                                  (tool/unit-graph.py lint refuses a model that has them). ConflictedBy must list
#                                  exactly the window units that list this one under Conflicts (systemd reports the
#                                  reverse edge that way; one from a unit outside the set is not simulated: lint refuses)
#   observed-stop <name> <unit>... behaviour seen on a real target that no declared dependency explains: simulated by
#                                  test-window.sh, never compared (systemctl show cannot see it). When a stop reaches
#                                  <name> (explicit, Conflicts, propagated, or another observed-stop line), the units
#                                  listed go down as if stopped: their own dependents and observed-stop lines follow.
#                                  Record only what was seen
#
# Propagation the fake applies (systemd semantics): stop of X reaches every unit that lists X under Requires,
# Requisite, BindsTo or PartOf (transitively), and each unit that goes down brings its observed-stop line (to a fixed
# point); restart of X is that stop, then the start of X, then the start of the units of X's stop closure that were
# active before (try-restart, through the same start path; the fake always starts X first, as After= would order a
# dependent); start of X pulls in X's Requires, BindsTo and Wants (also when X is already active, and also when X
# itself then fails to start), stops every unit X conflicts with (Conflicts in either direction; that stop takes along
# what an explicit stop would, also when X is already active), and fails if a Requisite unit is not active.
